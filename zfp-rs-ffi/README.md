# zfp-rs-ffi

C ABI bindings layer around the pure-Rust `zfp-rs` implementation.

This crate mirrors the API surface of `zfp-sys` (generated from `#include <zfp.h>`), providing zero-cost FFI adapters that delegate to the existing `zfp-rs` compression logic.

All ABI functions export upstream-compatible `zfp_*` and `stream_*` symbol
names, so C consumers can include the generated `zfp.h` and link
`libzfp_rs_ffi.a` in place of the upstream C library.

## Scope

The target API is `zfp-sys` version `0.4` as generated in this workspace. This includes `stream_*` functions except `stream_set_stride` (not enabled in `zfp-sys`), and excludes CFP APIs.

## Module Layout

| Module | Description |
|--------|-------------|
| `abi` | C-compatible type definitions (structs, enums, constants) |
| `bitstream` | Bitstream operations (`stream_open`, `stream_close`, etc.) |
| `block` | Block-level encode/decode (`zfp_encode_block_*`, `zfp_decode_block_*`) |
| `field` | Field descriptor operations (`zfp_field_*`) |
| `header` | Header operations and config constructors |
| `promote` | Type promotion/demotion utilities |
| `stream` | Stream operations (`zfp_stream_*`) |
| `util` | Helper functions for type dispatch and slice construction |

## Building

```bash
# Build a C-linkable static library with exact zfp.h symbol exports
cargo build -p zfp-rs-ffi

# Run tests
cargo test -p zfp-rs-ffi
```

## C header

The checked-in public C header is generated by `cbindgen`:

```bash
cbindgen zfp-rs-ffi \
  --config zfp-rs-ffi/cbindgen.toml \
  --output zfp-rs-ffi/include/zfp.h \
  --quiet
```

Consumers that want the Rust implementation only can include
`zfp-rs-ffi/include/zfp.h` and link `libzfp_rs_ffi.a`; they do not need the
upstream zfp headers or library.

## Compatibility Tests

The compatibility tests compare `zfp-rs-ffi` against the upstream C
implementation. Because both implementations export the same C symbol names,
the tests load the upstream shared library with `dlopen`/`libloading` instead
of linking it into the Rust test binary.

```bash
cargo test -p zfp-rs-ffi --test ffi_compat
```

## C drop-in test

`tests/c-dropin` is a small CMake project whose `compress.c` includes `zfp.h`
and uses the normal C API to compress and decompress data. The
`ZFP_DROPIN_BACKEND` CMake cache variable selects the provider of those symbols:

```bash
# Build and run against the upstream C zfp library
cmake -S zfp-rs-ffi/tests/c-dropin -B target/c-dropin-c \
  -DZFP_DROPIN_BACKEND=c \
  -DZFP_SOURCE_DIR=$PWD/zfp
cmake --build target/c-dropin-c
ctest --test-dir target/c-dropin-c --output-on-failure

# Build and run the same C source against zfp-rs-ffi
cargo build -p zfp-rs-ffi
cmake -S zfp-rs-ffi/tests/c-dropin -B target/c-dropin-rust \
  -DZFP_DROPIN_BACKEND=rust \
  -DZFP_RS_FFI_LIBRARY=$PWD/target/debug/libzfp_rs_ffi.a \
  -DZFP_INCLUDE_DIR=$PWD/zfp-rs-ffi/include
cmake --build target/c-dropin-rust
ctest --test-dir target/c-dropin-rust --output-on-failure
```

The cargo integration test `tests/c_dropin.rs` runs both configurations.
